Folio 1.0.7 final qualification trigger
Candidate: stale-preview race fixed and non-print reader switches are geometry-only
Paperwhite Standard uses the calculated 17.5px base font with the normal 28px logical side inset.
Editor chrome no longer repeats the book title above the chapter heading; the left side of that top bar is intentionally empty and save/word-count stay right-aligned.
English a/an/the are structurally bound to the following word while preserving discretionary hyphenation inside that following word; visual QA rejects stranded English articles.
Local editable live preview uses draftRef as the authoritative draft. Every server preview records the exact draft snapshot it represents, so a late response cannot masquerade as current HTML or erase newer typing.
Pending iframe srcDoc loads carry the represented-draft snapshot too; once loaded, Folio patches any newer append-only tail from the current editor model before composition.
Huge-manuscript fast typing finds the last direct prose paragraph by walking backward from the tail instead of allocating/scanning all 5,200 paragraphs for every keystroke.
Switching between Kindle, tablet and phone profiles no longer triggers a server manuscript rebuild; only transitions into or out of Print may regenerate preview HTML. Reader device/profile changes otherwise use the dedicated geometry-only refresh path.
Discarded previews explicitly dispose their lazy compositor observer before iframe teardown, preventing a 5200-paragraph manuscript from starving the next project's first live preview.
Windows Polish-composition timeout diagnostics remain hard-gated; no responsiveness timeout or quality threshold was raised.
Runtime QA normalizes discretionary soft hyphens when checking typed text and validates the optical edge against the compositor's declared bounded protrusion. The right-edge residual remains <= 1.75px and protrusion itself is capped at 4.5px.
English relaxed compression remains at the conservative 0.07em profile; Polish relaxed compression remains at 0.0595em. Polish strict fitting may use bounded compression up to 0.085em as an alternative to an extra discretionary hyphen; the 0.101em release spacing ceiling remains unchanged.
The compositor now prefers a 0.40 hyphen-rate operating target whenever a strict feasible state exists, preserving cross-platform headroom while the immutable release ceiling remains 0.45.
Release quality gates remain unchanged: hyphen rate <= 0.45, streak <= 2, relaxed lines <= 2, zero emergency ragged lines, zero one-word final lines, bounded spacing/tracking/scaling, justified drop-cap opening lines.
